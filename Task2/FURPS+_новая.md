| Код | Требования                           | Комментарий    |
| --- | ------------------------------------ | -------------- |
| F   | Функциональные (Functionality)       |                |
| F1  | На сайте новый клиент видит список   |                |
|     | доступных депозитов с актуальными    |                |
|     | ставками.                            |                |
| F2  | Клиент подаёт заявку на депозит,     |                |
|     | оставив номер телефона и Ф. И. О.    |                |
|     | Менеджер кол-центра звонит клиенту   |                |
|     | и, изучив заявку, может предложить   |                |
|     | особые условия.                      |                |
| F3  | В интернет-банке клиент видит        |                |
|     | список депозитов с актуальными и     |                |
|     | персонализированными ставками.       |                |
| F4  | Клиент указывает счёт и сумму        |                |
|     | депозита и подаёт заявку на          |                |
|     | открытие депозита.                   |                |
| F5  | Операция открытия депозита           |                |
|     | подтверждается СМС-кодом.            |                |
| F6  | На этапе MVP заявку обрабатывает     |                |
|     | менеджер бэк-офиса: подтверждает     |                |
|     | условия депозита в АБС.              |                |
| F7  | Клиент получает СМС-уведомления      |                |
|     | после подтверждения ставки и         |                |
|     | открытия депозита.                   |                |
| F8  | Ставки по депозитам ведутся в        |                |
|     | системе (сейчас только в XLS).       |                |
|     | Сотрудники бэк-офиса депозитов и     |                |
|     | кредитов работают со ставками.       |                |
| F9  | Процесс согласования ставки по       |                |
|     | заявке реализован в АБС.             |                |
| F10 | Заявка с сайта передаётся в          |                |
|     | систему кол-центра для               |                |
|     | обработки менеджером.                |                |
| F11 | При открытии депозита в АБС          | Отдельная      |
|     | формируется договор (бизнес-         | бизнес-        |
|     | способность «Управление              | способность    |
|     | договорами» в АБС).                  | в IT ландшафте |
| U   | Удобство использования (Usability)   |                |
| U1  | Интерфейс максимально удобен         |                |
|     | для клиента.                         |                |
| U2  | Соблюдение системы дизайна:          |                |
|     | привычные цвета и брендированные     |                |
|     | элементы интерфейса.                 |                |
| R   | Надёжность (Reliability)             |                |
| R1  | SLA: 99,95% доступность (макс.       | SLO: 99.9%     |
|     | допустимое время простоя 21.6 мин    | на пиковых     |
|     | в месяц). SLO: 99.9% доступность на  | часах.         |
|     | пиковых часах (10:00-17:00 МСК).     | Исключение:    |
|     | Измеряется от конечного пользователя | техническое    |
|     | (синтетический мониторинг каждые     | обслуживание   |
|     | 5 минут, реальные транзакции каждые  | запланировано  |
|     | 30 сек). Максимально допустимое      | по будням      |
|     | время инцидента (MTTR): 15 минут     | 22:00-6:00.    |
|     | для критичных, 30 мин для важных.    |                |
| R1a | RTO (Recovery Time Objective):       |                |
|     | 15 минут для открытия депозитов,     |                |
|     | 30 минут для интернет-банка.         |                |
|     | RPO (Recovery Point Objective):      |                |
|     | не более 5 минут потери данных       |                |
|     | (синхронная репликация БД,           |                |
|     | резервные копии каждые 5 минут).     |                |
| R2  | При сбоях в ЦОД: сервисы             |                |
|     | интернет-банка переключаются на      |                |
|     | резервный ЦОД не более чем за        |                |
|     | 2 минуты. Выдерживают нагрузку       |                |
|     | 5000 RPS на операцию открытия        |                |
|     | депозита (р95 < 200 мс, p99 < 500    |                |
|     | мс). Кэширование справочных данных   |                |
|     | (кэш жив 5 минут, TTL обновления     |                |
|     | 1 минута).                           |                |
| R3  | Исключить прямую работу              |                |
|     | интернет-банка с API АБС в новом     |                |
|     | процессе. Использовать очередь       |                |
|     | сообщений (Kafka) и асинхронный      |                |
|     | обработчик для разделения нагрузки.  |                |
|     | БД АБС перегружена.                  |                |
| R4  | Правила отказов и ретраев:           |                |
|     | - Soft fail: таймауты > 3 сек для    |                |
|     | интеграций, 2 ретрая с expo backoff  |                |
|     | (1 сек, 2 сек).                      |                |
|     | - Hard fail: > 3 отказов подряд →    |                |
|     | circuit breaker, fallback режим      |                |
|     | (закэшированные данные).             |                |
|     | - Логирование всех отказов с         |                |
|     | трассировкой ошибок (request ID).    |                |
| P   | Производительность (Performance)     |                |
| P1  | Времена отклика по операциям:        |                |
|     | - Открытие депозита: p95 < 200 мс,   |                |
|     | p99 < 500 мс, max 1000 мс.           |                |
|     | - Получение списка депозитов:        |                |
|     | p95 < 100 мс, p99 < 300 мс.          |                |
|     | - Подтверждение СМС: p95 < 50 мс,    |                |
|     | p99 < 150 мс.                        |                |
|     | - Утвердительные для всех остальных  |                |
|     | операций: p95 < 300 мс, p99 <        |                |
|     | 800 мс.                              |                |
| P2  | Загрузка справочных данных           |                |
|     | (ставки, условия депозитов):         |                |
|     | - Холодный старт: < 1 сек.           |                |
|     | - С кэша: < 50 мс.                   |                |
|     | - Обновление: асинхронное, не        |                |
|     | блокирует пользователей.             |                |
| P3  | Пропускная способность и масштабы:   |                |
|     | - Выдержать пик 5000 RPS на          |                |
|     | операцию открытия депозита           |                |
|     | (в пиковые часы возможен рост).      |                |
|     | - Горизонтальное масштабирование     |                |
|     | приложений (minimum 3 инстанса для   |                |
|     | HA). Распределение запросов          |                |
|     | между серверами через балансер       |                |
|     | нагрузки. Максимальная задержка      |                |
|     | на синхронизацию состояния между     |                |
|     | инстансами: 100 мс.                  |                |
| P4  | Высокая нагрузка от онлайн-заявок    |                |
|     | (очередь Kafka):                     |                |
|     | - Не снижает производительность      |                |
|     | критичных систем банка (АБС).        |                |
|     | - Асинхронная обработка заявок:      |                |
|     | latency до очереди < 100 мс,         |                |
|     | время обработки в фоне ~1-5 мин.     |                |
|     | - Гарантия обработки: at-least-once  |                |
|     | (deduplicate на стороне АБС).        |                |
| S   | Поддерживаемость (Supportability)    |                |
| S1  | Разработать документацию для         |                |
|     | дальнейшего расширения системы.      |                |
| S2  | Рассмотреть перевод интернет-банка   |                |
|     | на микросервисную архитектуру        |                |
|     | в рамках задачи открытия депозитов.  |                |
| +R  | + Ограничения (Restrictions)         |                |
| +R1 | Новый клиент обязан посетить         |                |
|     | отделение для идентификации          |                |
|     | личности (требование законодатель-   |                |
|     | ства).                               |                |
| +R2 | Безопасность трафика — TLS 1.2+      |                |
|     | (минимум). Шифрование данных:        |                |
|     | - При передаче: TLS 1.3 preferred,   |                |
|     | TLS 1.2 minimum (для старых          |                |
|     | клиентов). Cipher suites: только     |                |
|     | криптостойкие (не RC4, не DES).      |                |
|     | - В базе: чувствительные данные      |                |
|     | (номер счета, сумма) — AES-256.      |                |
| +R3 | Логирование и аудит:                 |                |
|     | - Все операции с заявками:           |                |
|     | timestamp, user ID, IP, результат.   |                |
|     | - Изменения ставок: кто, когда,      |                |
|     | старое/новое значение (audit trail)  |                |
|     | - Хранение логов: 7 лет.             |                |
|     | - Целостность логов: ЭЦП или хэш     |                |
|     | (защита от подделки).                |                |
| +R4 | Функционал СМС реализован в ядре     |                |
|     | системы силами команды разработки    |                |
|     | банка (без привлечения подрядчика).  |                |
| +R5 | При доработках использовать          |                |
|     | существующие технологии банка        |                |
|     | (MS SQL, Oracle). Новые технологии   |                |
|     | совместимы с платформами и понятны   |                |
|     | команде банка.                       |                |
| +R6 | Для очередей сообщений использовать  |                |
|     | Kafka. Текущий интернет-банк         |                |
|     | несовместим с ней — требуется        |                |
|     | учитывать при планировании.          |                |
| +R7 | АБС масштабируется только            |                |
|     | вертикально из-за ограничений БД.    |                |
| +R8 | Уточнить роль партнёрского           |                |
|     | кол-центра в новом процессе:         |                |
|     | нужна ли интеграция с его системой.  |                |
| +R9 | Сайт и интернет-банк развёрнуты      |                |
|     | в контуре АБС — архитектурная        |                |
|     | связанность учитывается при          |                |
|     | переходе на микросервисы.            |                |
